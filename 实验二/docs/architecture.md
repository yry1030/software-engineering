
# 校园二手交易系统——初始模块划分

## 1. 项目概述

本项目为校园二手交易系统，面向买家、卖家和管理员三类用户，支持商品发布、审核、查询、预约、线下交易结果确认及后台管理。

系统不包含在线支付、物流配送、即时聊天、推荐算法、信用评分和真实学籍认证。

## 2. 功能模块划分

### 2.1 用户与权限管理模块
- 用户注册与登录
- 买家、卖家、管理员角色管理
- 管理员邀请码管理
- 数据访问权限与联系方式访问控制

### 2.2 商品管理模块
- 创建商品草稿
- 修改商品信息
- 提交商品审核
- 商品普通下架
- 商品状态管理

### 2.3 商品查询模块
- 买家浏览和搜索已发布商品
- 卖家查询自己的商品
- 管理员查询全站商品
- 关键词、分类、价格、状态筛选与分页

### 2.4 商品审核模块
- 管理员审核商品
- 审核通过或驳回
- 管理员发起违规下架，联动处理当前待审核记录
- 审核历史记录管理

### 2.5 预约与交易管理模块
- 买家创建预约
- 卖家确认或拒绝预约
- 买家取消预约
- 买家确认线下交易完成
- 响应违规下架，关闭当前有效预约并保留历史记录
- 预约历史记录查询

### 2.6 统计与日志管理模块
- 商品状态统计
- 关键业务操作日志记录
- 管理员日志查询

### 2.7 数据持久化与一致性模块
- 用户、商品、预约、审核、日志及邀请码数据存储
- 数据唯一性约束
- 并发预约控制
- 跨记录事务一致性
- 历史数据与快照保存

## 3. 总体架构

系统初步采用分层架构：

1. 表示层：提供买家、卖家和管理员的 UI 界面。
2. 业务逻辑层：实现各功能模块及业务规则。
3. 数据访问与持久化层：负责数据访问、事务及一致性控制。
4. 数据存储：保存业务记录和商品图片。

## 4. 后续检查事项

- 检查功能模块是否覆盖实验一全部已确认需求。
- 检查模块职责是否存在重叠。
- 检查商品与预约状态变化是否符合需求。
- 检查权限控制与跨记录事务设计是否合理。
